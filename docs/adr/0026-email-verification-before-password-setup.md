# 邮箱注册在站内验证成功后设置并确认密码

2026-09-07，已接受。影响平台为 shared（Web/API）。

用户反馈旧流程在提交邮箱、密码后还必须打开邮件链接并重复填写邮箱。新顺序固定为
“填写邮箱 → 六位验证码 → 设置密码与确认密码 → 完成注册”，验证邮件链接不再是必经步骤。

Web 在 `/join` 展示各阶段，通过独立 HttpOnly 注册 Cookie 恢复原浏览器的进度。服务端绑定邮箱，
验证码通过后仅保存加密 Provider state。设置密码并证明同一身份后，才使用既有邀请完成事务登记
password method、创建业务账号及 Web session。注册证明不能访问业务 API。

沿用 Supabase signup/verifyOtp/updateUser 适配器：signup 使用随机临时密码，此值不交付客户端或持久化；
用户密码只在验证成功后提交。认证系统仍由服务端访问，不引入浏览器 Supabase session。

通过密文 CAS 串行推进；有界恢复允许原浏览器在 claim 创建后 24 小时内、原邀请仍有效时继续，
每次写入只续期最多 15 分钟，不恢复撤销或已完成的邀请。旧注册邮件与中断恢复保持兼容。

代价是新增五个窄注册端点与两个受信 SQL 函数，部署前需要应用 forward-only 0026 迁移。
实现与验收边界见 [邮箱优先注册](../cloud-v1/email-first-password-signup.md)。
