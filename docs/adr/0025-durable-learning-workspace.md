# 查询与学习使用持久任务，业务结果保持原权威

2026-09-05，已接受；本地实现，尚未部署或执行迁移。

用户划词后关闭卡片、滚动页面或离开 Web，不应使已付费的生成丢失、重复调用或锁住页面。
采用 Postgres LearningTask 保存提交身份、租约、游标、进度与取消状态，独立 worker 执行模型；
pg_net 只唤起 worker，现有 Supabase pg_cron 补偿遗漏。提交与完成均唤起下一次领取。

任务共享调度，但 QueryGeneration、AnalysisRecord、PracticeSession、查重记录继续分别保存权威
结果和计费关联。同账号至多一个运行任务及一个有效费用预留。交互任务优先于未开始的深度分析，
不抢占已派发调用。每个被合并的提交键也持久绑定原任务，响应丢失后的重试不能新建一次计费。
结果过期后保留无正文的幂等键墓碑，旧键被拒绝而不是自动再次生成。

派发前每次核对任务租约与取消状态；已派发且结果不明只对账。练习已耐久保存的 ready 输出可通过
原领域完成事务补偿应用，恢复路径不可访问 Provider 或取得新费用预留。

卡片显示、成功结果缓存与生成有不同生命周期。Service Worker 缓存限定有效身份、30 条/30 分钟/
2 MiB；关闭只断开订阅，显式停止才请求取消。Web 练习另存工作状态与草稿版本，暂停不改变作答
版本，结束或换模式才使旧作答失效；自评继续是唯一推进排期的动作。

代价是新增队列表和单独的调度配置；只有迁移与 worker 唤起配置都安装后，Hosted 后台任务才可运行。
