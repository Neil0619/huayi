# 语见扇贝回填

## 范围与开启

本文描述当前工作区的 `ShanbayBackfill` 实现，适用平台为 shared（macOS/Windows Chrome）。源码、
离线测试和构建结果不代表已部署、已安装或已通过真实欧路/扇贝网站验收；不同构建目标的发布证据
必须分别记录。

扇贝回填默认关闭。设置页“外部词典”分类提供“开启扇贝回填”“检查新词”“打开扇贝回填”“需处理”和
“停用”。“需处理”只打开或聚焦扇贝生词页，并展开右下角处理面板；弹窗和设置页不渲染编辑列表。
用户主动开启时确认三种来源、首次包含已有词、检查频率、账号共享范围及逐批人工提交。
开启会授予当前扇贝披露同意并启用扇贝；欧路仍独立要求当前同意、启用和本机 Authorization。

弹窗里的回填卡片由“设置 → 外部词典 → 扇贝单词 → 在弹窗显示扇贝回填卡片”独立控制，默认不展示。
此开关保存在本机插件中，对当前插件的所有网站和账号生效；未保存或配置无效时保持隐藏。
打开后才挂载卡片并读取回填状态，关闭时移除卡片及其监听，避免隐藏卡片仍拖慢弹窗。
这个显示偏好不启停回填、不修改队列、账号授权或角标；后台检查和扇贝页右下角面板沿用原行为，
设置页“外部词典”入口始终保留。

“预填到扇贝单词”是扇贝词头外发的启停开关，需要已有有效的数据范围同意；它会限制页面领取和预填、
旧版任务及本机收藏的扇贝导出，不控制弹窗是否显示。回填卡片里的“开启／停用”另行控制来源检查和
回填队列运行。因此，想继续回填但隐藏弹窗卡片时，应保留扇贝预填开启，只关闭显示开关。

| 来源     | 发现方式                                                   | 进入回填的数据                 |
| -------- | ---------------------------------------------------------- | ------------------------------ |
| 本机收藏 | 扩展读取本机生词快照；保存新词后也触发发现                 | 合法规范词头                   |
| 欧路     | 扩展使用本机凭据读取固定分页接口                           | 合法规范词头，不复制解释或语境 |
| 云端生词 | 连接账号后，由 API 在当前账号范围内分页读取 `word_entries` | 已有云端生词的规范词头         |

只接受规范化后最长 200 字符的英文词头，可包含词内撇号或连字符；短语和非法输入不进入回填。
同一词可记录多个来源。欧路和本机上传的是词头及必要回填进度，不创建云端 WordEntry、
ContextObservation 或 LearningItem，也不触发模型分析、学习项采集或生词复制。

无账号时，本机和欧路发现结果保存在当前扩展的加密回填库。有云端能力的构建在连接账号并确认
共享后，以 API 的账号状态为权威。各设备须使用同一个扇贝账号；语见不能读取或验证扇贝账号
身份，也不能枚举扇贝完整词表，不能把本地账本当作扇贝全量数据的实时镜像。

## 检查与分页

- 弹窗和设置页读取本机加密的最近状态，不等待来源检查或云端请求。后台更新后，只刷新数量与检查
  进度，不清空已有显示、不禁用“打开扇贝回填”。读取失败保留最近有效数量并提示错误；换账号、
  连接过期或尚未建立安全的账号绑定时，不展示前一个账号的缓存。
- 打开弹窗只读状态，不触发新词扫描；“检查新词”安排后台工作，重复请求合并。“打开扇贝回填”
  先打开或聚焦固定扇贝页面，不发起欧路检查；页面领取批次仍须通过账号、权限与持久化检查。
- 首次欧路检查包含默认生词本（`category_id=0`）已有的历史词，不按添加日期筛选；不会加载欧路
  整部词典。数字代表三个来源去重后、缺少明确扇贝成功或跳过记录的目标数量，分页期间可能增长，
  并不是“今天新增的词数”。语见不会读取扇贝完整词表作差。
- 欧路默认按设备本地时间每天 08:00 检查；Chrome Alarm、启动恢复或手工检查驱动实际执行。
  浏览器未运行时不保证准点，恢复后按最近一次完成的检查时间判断是否需要补查。
- 另一个 Alarm 每 15 分钟刷新云端和本机发现状态。首次开启和“检查新词”可立即检查。
- 单次检查推进一个云端页面和至多一个欧路页面；有后续页时保存游标/页码，再安排约 30 秒后的
  继续检查。欧路从页 0 开始，每页 100 词，最高页 50；页 50 仍满页时标记“不完整”，不声称全量成功。
  云端按词条 ID 游标每页 100 条读取；完成一轮后下轮重新扫描，可发现以后新增的词头。
- 检查点、最近完成时间、分页不完整和稳定错误持久化；检查失败保留已有待回填数量。Badge 优先显示
  待回填目标数，上限 `999+`；没有待回填目标但有待处理项、结果未知或检查异常时显示 `!`。
- 欧路可选语境为空或只有空白时按无语境处理，不让单条空语境中断整页词头发现；非空语境仍校验
  原有长度上限。授权失效、缺少授权、网络、超时或数据格式异常分别显示固定提示。
- 单次来源检查失败会保留已开启设置、已有队列和检查进度；“打开扇贝回填”仍可打开已有队列。
  账号鉴权失效、账号变化、持久化失败或扇贝权限不足仍会阻止操作，不能绕过这些检查。
- 没有需处理来源和结果未知批次时，“需处理 (0)”不可点击，不再展开空列表。
- 停用回填后不再发现或认领新批次；停用不删除已有进度，也不删除扇贝中的数据。已提交但回执未定的
  项目仍需按结果未知流程核对，不能把停用解释成撤销第三方写入。

## 来源、目标与逐批提交

领域核心分别维护来源记录、目标账本和批次。来源保留原始规范词头、当前目标、来源集合、
`original | lemma | manual` 尝试类型及 `pending | confirmed | unresolved | discarded` 状态。
目标账本以实际发送给扇贝的词头去重，并用 `confirmedAt` 保存成功证据。多个来源指向同一个目标时
只占一个目标名额；目标成功会结清所有尚未跳过且指向它的来源。

1. 用户从 Popup/Options 打开或复用精确收藏页
   `https://web.shanbay.com/wordsweb/#/collection`。复用通过既有顶层 Content Script 的空数据
   `store/backfill-probe` 确认；Worker 只枚举 tab ID，不读取 tab URL，不新增 tabs/host 权限。
2. 每批最多认领 **100 个不同目标词**，默认租约为 5 分钟。`prepared` 或 `unknown` 批次中的目标不会
   再被其他批次认领，token 永不复用。
3. 页面可打开“批量上传”窗口，并向空输入框或仍属于本批的未改动输入框预填词头；不覆盖用户编辑。
4. **每一批**都必须由用户亲自点击扇贝“批量添加”。生产判断使用 `event.isTrusted`，提交时输入还须
   与本批一致。程序不会点击最终添加按钮。
5. 只接受该次真实点击后新增的明确成功/失败反馈。成功与失败集合必须无重复、无遗漏、无额外词地
   分区整个当前批次；旧提示、合成点击和迟到回执不能确认成功。
6. 回执持久化成功后可准备下一批，但下一批仍需新的真实点击。只有前一批提交后的输入仍未被用户
   编辑且可证明属于前一批，才允许清理并换入下一批。

页面适配兼容扇贝实际的 `div` 上传/提交控件和批量窗口内的结果提示；提交控件必须属于当前
输入框所在窗口且唯一、可用。预填通过原生 textarea setter 通知受控页面更新，避免只改变可见
文本而没有更新扇贝内部待提交词表。点击后显示等待结果，识别后显示保存回执，保存成功才减少数量。
结果新鲜度同时检查节点身份与文本变化，连续两批相同的“添加完成（100/100）”仍须分别识别；旧提示、
窗口外提示、互相矛盾的结果及语见自己的提示不能充当回执。

旧版本漏识别的上传没有成功回执，不会因升级或“检查新词”自动追认为成功。检查新词只发现来源词，
不反查扇贝完整生词本。已进入“结果待确认”的历史批次仍须按下述核对流程处理。

原词被明确拒绝时，随包纯词元算法依次计算名词、动词和形容词候选。只有去重后恰好存在一个合法、
不同的候选，才排入一次词元重试；不调用模型或词元网络服务。词元再次被拒绝、没有唯一候选或手工
替换后被拒绝，都进入“需处理”。用户可以“修改并重试”或“跳过”；重新发现不会复活已跳过的来源。

右下角面板统一展示未解决词与结果待确认批次，支持修改目标、重试、跳过、分页和收起。
待回填批次全部结束后自动展开；修改后的词先回到待回填队列，点击“继续回填”再预填，仍需真实
点击“批量添加”。刷新保留未提交的目标输入；账号或页面授权失效时清除旧数据。列表版本冲突
保留草稿并要求刷新，旧批次的迟到续租或回执不能影响后来领取的批次。

右下角面板展示未解决原因：无可靠原形、多个候选、原形已拒绝或手动目标已拒绝。候选按钮只填入
目标输入框，修改并重试仍需用户操作。词元使用与 Classic 相同的本地规则，例如 `walking → walk`、
`went → go`；`axes` 有 `ax / axe` 两个候选，不自动选择。无可靠候选的缩写不会任意猜词。
若原词与唯一原形在同一批次均被拒绝，不重复排入已拒绝的原形。

“跳过”只保存当前行，其他行保持可编辑；收到持久化回执后移除该行并更新数量，不重新读取整个列表。
已关联账号时仍保存云端记录，以便跨设备共享并防止后续扫描再次提醒；使用已验证且绑定当前 session
的缓存发起一次带版本检查的命令，服务端仍校验身份、权限和版本。保存中显示行内进度；断网、超时或
冲突不能显示成功，保留输入并要求刷新。原有幂等恢复继续使用同一命令与键，不生成新的重复操作。

“全部丢弃（数量）”经再次点击确认后，处理当前账号所有分页的未解决词和结果待确认批次。
确认说明紧邻按钮，并提供“取消”；数量包含两类待处理项。页面和弹窗分别显示“需处理”与“待确认”，
不再把结果不明误写成词语失败。批次默认折叠词表，支持整批“不再提醒”或经核对后重新预填。
不再提醒只结束语见回填提醒，不删除扇贝、欧路或学习库中的单词，不记录添加成功，也不自动重发。
全部处理完毕后显示“已处理完毕，可以收起”，隐藏无效的零数量操作；待回填词仍提供继续入口。

新版全局操作使用 `{ action: "discard-review", expectedRevision }`，单批使用
`{ action: "discard-unknown", token, expectedRevision }`。旧 `discard-unresolved` 的语义保持不变。
命令在账号事务中保存；失败完整回滚，超时不假报成功。正在提交的 prepared 批次及其占用来源保留，
处理后仍有占用项时重新读取列表，不隐藏未完成内容。

未知批次可带可选 `dismissedAt`，保留 unknown 状态及目标占用，以防旧手动导出或后续扫描再次发送。
已丢弃目标不再进入待确认列表和角标；旧 token 的重试不能撤销决定，后续到达的来源继承丢弃状态。
这个字段不构成成功回执。未知证据先于来源上传的中断场景也保留决定；本机共享通过可选
`adopt.dismissed` 分页传递词头和丢弃时间，每个请求合计最多 100 个词，不添加虚构来源。

词元代码与字典随扩展打包，`shanbay-lemma-licenses.txt` 保留 wink-lemmatizer 的 MIT 及 wink-lexicon
的 MIT/WordNet 3.0 完整声明。回填不调用扇贝 HTTP API，也不加载远程词元代码或词典。

提交后 30 秒内没有可靠反馈、续租失败、租约过期、页面/文档切换或回执保存不确定时，批次保守地
进入 `unknown`（结果待确认），不自动重发。页面活动期间约每分钟续租；过期租约不能续期或确认。
“核对后重试”要求用户先在扇贝检查结果并明确确认重新预填，随后才解除该未知批次对目标的占用。
该操作不是成功回执，也不能自动证明扇贝中不存在这些词。

## 旧任务与迁移

云端回填与原有手动扇贝导出任务共享账号行锁、目标账本和被占用目标集合，按同一顺序取得锁，避免
新旧路径重复认领同一目标。手动任务成功回执能结清回填目标；回填成功也能结清对应手动任务。
原有手动任务仍在执行或结果未知的目标不会直接重新发送。

数据库迁移 `0039-shanbay-backfill.sql` 只把 `target=shanbay`、`direction=export`、
项目 `state=delivered` 且回执为 `{ target: "shanbay", outcome: "confirmed" }` 的合法词头计入成功
账本。任务级 completed、欧路成功、失败、取消和无回执记录都不构成扇贝成功证据。旧未完成来源可在
运行时被发现；旧在途租约纳入占用，无法证明结果时保留 unknown。迁移不会自动开启回填。

本机共享迁移先上传全部已确认目标与结果未知的占用证据，再分段迁入来源；每段最多 100 项，
迁移阶段、游标和未完成命令先持久化。来源记录自身的 `confirmed` 状态不能替代目标成功证据；
没有独立证据时恢复为待处理。发现/迁移接口每段最多 100 项，与网页每批最多 100 个目标词分别校验。

## 账号隔离与重新连接

- 账号 scope 由 API 返回，客户端不能指定 owner。每个 scope 独立保存检查点、最近状态、未完成命令
  和共享确认。账号变化时清除当前页面关联，旧 UI generation、`expectedScope`、旧 session 和旧页面
  alias 不得写入新账号。
- 本机历史一旦迁入某账号，`migratedTo` 固定其归属。断开账号后不恢复本机认领；界面提示
  “本机进度已共享，请连接原账号后继续”。迁移中断也应连接原账号继续已保存阶段。
- 改连其他账号不会复制原账号历史、成功账本或待发送命令。用户在新账号主动开启时，把当时现有本机
  词头记为 baseline（排除集合），这些词不会以本机来源上传；以后出现的不在 baseline 中的新词头
  仍会被发现。已有词新增语境不算新词头。新账号自己的云端词和已同意的欧路来源仍独立检查。
- 本机加密状态与账号权威各有边界。清除扩展数据不会删除云端账号回填状态；删除账号按既有数据权利
  流程级联删除云端回填表，不会删除欧路或扇贝副本。

## 消息、API 与存储边界

当前页面消息为 `store/backfill-page-ready`、`store/backfill-renew`、`store/backfill-resolve` 和
`store/backfill-unknown`，另有 `store/backfill-page-review`、`store/backfill-page-review-replace`、
`store/backfill-page-review-discard`、`store/backfill-page-review-discard-all`、
`store/backfill-page-review-discard-unknown` 和
`store/backfill-page-review-retry-unknown`。Worker 发出的
`store/backfill-activate` 可携带 `view: "review"`，只激活已登记页面；可信 `store/backfill-open`
同样使用该可选字段。仅打开处理面板不会认领批次。页面只取得每页最多 100 项的可见词头、目标、
数量、处理原因、最多三个词元候选及随机 source/batch/cursor alias；真实云端 token、holder、scope、revision 和游标不进入页面。
处理映射加密持久化并绑定当前账号身份、tab/document 和版本，翻页/刷新后旧 alias 失效；结果未知
批次只能通过已显示的随机 alias 核对后重试或不再提醒，不能提交真实云端 token。新版可读取未带 dismissedAt 的旧加密库。
Worker 同时校验当前扩展 ID、精确收藏页 URL、顶层 frame、已登记 tab/document、当前账号、当前
扇贝同意及站点策略；仅匹配 URL 的其他标签页不能取得批次。可信扩展界面的 status/enable/check/
open/unresolved/replace/discard/retry-unknown 消息也使用 strict Schema，不接受页面提交的 URL、
凭据、owner 或租约 holder。旧 `store/shanbay-page-ready` / `store/shanbay-resolve` 不能作为当前
回填流程的契约说明。

`store/backfill-status` 是纯缓存读取；首次账号状态获取失败后，可信界面的
`store/backfill-initialize` 显式安排后台重试，不让存储通知或普通状态读取重新触发检查。

可信界面只接受当前扩展的精确 `popup.html` 或 `options.html`，拒绝 query/hash 和已知的非顶层
frame。Options 在标签页打开时正常携带 `sender.tab`，该字段不表示来源不可信；其他扩展页面仍
不可调用这些操作。

| API                                   | 权限与作用                                                |
| ------------------------------------- | --------------------------------------------------------- |
| `GET /v1/shanbay-backfill/status`     | 已认证账号读取设置、revision、scope 和数量                |
| `GET /v1/shanbay-backfill/unresolved` | 已认证账号按游标读取需处理来源与未知批次，每页最多 100 项 |
| `POST /v1/shanbay-backfill`           | strict action 命令及必需的 `Idempotency-Key`              |

Extension 请求使用 `Authorization: HuayiExtension …`、运行时自身的 `Origin` 和
`X-Huayi-Client-Version`；服务端验证固定扩展 origin、启用状态、最低支持版本、有效未撤销 session
及 active 账号。租约 holder 从已配对安装的服务端身份取得，客户端不能声明。Web 写入要求 Cookie、
可信 Origin 与 CSRF；Web 只能管理设置、reconcile、replace、discard、批量丢弃、不再提醒和 retry-unknown，不能发现、
迁移、认领、续租或确认页面回执。小程序只可读取，所有回填 POST 均拒绝。

settings/replace/discard/discard-unresolved/discard-review/discard-unknown 带 `expectedRevision`，冲突要求刷新。命令重放以账号、幂等键和
holder/command 摘要绑定，同一键的不同请求拒绝；扩展对不确定响应保留原命令与同一键，不能盲目
重新创建 claim。新版扩展显式发送 `claim.limit=100`，允许范围为 1–100；省略 limit 的旧客户端仍
领取最多 20 词，旧请求的幂等摘要不变。已经领取的 20 词批次按原回执完成，不自动扩大或释放。
部署顺序为先更新 Hosted API，再重载新版扩展；旧 API 会拒绝新增字段，不自动换形状重发领取。
一旦保存过超过 20 词的批次，回滚 API 也须保留 100 词存储读取能力，不能直接恢复旧的 20 词 Schema。
云端来源只允许服务器 reconcile，不能通过 discover 冒充。

本机状态使用 DeviceVault DEK、独立随机 IV、固定用途 AAD 的 AES-GCM envelope 保存到
`huayi.store.shanbay-backfill.v1`，写操作由 Web Locks 串行化并严格校验。缓存绑定由服务器验证的
账号 scope 和当前 session 的 SHA-256 指纹组成，一并加密保存；读取在前后核对 session，绑定不匹配
时返回初始化状态，不展示旧账号数量。缓存中不增加明文 token，也不向页面发送该指纹。
欧路读取在写锁之外进行，回来后重新验证账号、来源同意与页码再保存；领取、续租与回执仍经过
原权威路径。云端四张回填表全部启用并强制
owner RLS，在短账号事务中更新；本机页面与云端都不依赖 Service Worker 内存维持权威。

## 账号导出与发布证据

完整账号导出 **format 5** 在 format 4 记录之外加入专用的 `shanbay-backfill-settings`、
`shanbay-backfill-source`、`shanbay-backfill-target` 和 `shanbay-backfill-batch` 记录。
批次只导出词头、公开状态、到期时间及可选的不再提醒时间 dismissedAt，移除 token、holder；不导出安装标识、页面 alias、scope、
凭据、幂等记录或各设备未共享的本机库。format 1–4 维持既有 allowlist，不夹带回填记录。
迁移 `0040-backfill-account-exports.sql` 新增 `claim_account_export_v5`，旧 worker 的 claim 函数不变，
不能认领 format 5。详见[账号数据权利](../cloud-v1/account-data-rights.md)。

发布需分别核对标准未来商店包、Hosted 验收包和 production 包的 Manifest/API origin、产物、安装与
验收证据。所需离线覆盖包括三来源分页、100 目标去重、逐批真实手势、单次词元、unknown、迁移证据、
新旧任务并发、跨账号隔离及 format 5 权限/导出。真实 Chrome、欧路/扇贝账号、网站交互和数据库迁移
必须有对应目标的授权与实际结果；本文不把它们标为已完成。
