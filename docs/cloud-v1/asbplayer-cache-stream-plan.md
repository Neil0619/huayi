# 缓存直开与免目录选择

2026-09-25，影响 shared + Windows，基于 `1f4f139`。用户要求直接打开已处理视频，
原片准备后直接开始学习，不再复制缓存路径或再次选择目录；选择原片仍须优先复用有效缓存。

## 实现边界

- 新增原生「打开缓存视频」，读取相邻缓存记录和对应字幕。无需原片存在，不运行转换工具；
  缓存缺失、被修改或记录不匹配时明确拒绝，不将任意 MP4 当作可信缓存。
- 保留原片身份与缓存校验，明确展示命中缓存的结果。原片及用户已有文件不修改。
- 替换额外 File System Access 目录选择：仅为已经由本机选中的缓存签发随机只读播放地址，
  回环 HTTP 支持 Range，按需读取；不会先 fetch 整集再构造 Blob，不新增浏览器视频副本。
- 管理接口继续使用会话令牌、准确 Host/Origin、空请求体；播放地址仅允许已发布文件，
  不能携带任意路径，检查文件身份、方法、范围、Origin，并限制存活数量和生命周期。
- 官网文件输入集成使用专用于这一次导入文件的短期 MAIN world 适配，向上游提供播放地址；
  不读取 React 私有状态，不改变无关 File/Blob 行为。适配消费后或超时恢复原 API。
  上游仍非正式公共导入协议，必须用正式注册 Store 构建和官网验证，不能只依靠替身页面。
- 播放上下文只新增准确的本机流地址格式，不接受任意 HTTP、主机、路径或远端视频来源。
  不增加 Manifest 权限，不修改 Classic Native Host、浏览器安全设置或真实 Provider。

## 验证顺序

1. 缓存直开、原片命中缓存、不调用媒体工具、缓存损坏与越界记录先写失败回归。
2. 真实 HTTP 检查 Range/HEAD、错误令牌、Origin/Host、文件变化及失效能力。
3. 实际 Store 浏览器检查无目录选择、原片/缓存两种入口、批量选用、字幕及换片，
   并验证适配恢复和无关文件不受影响。
4. Windows 150% 实际两集缓存验证导入、声音、字幕、完整学习和换片；合成响应，无外部词典写入。
5. 运行适用完整门禁、更新安全/安装/跨平台说明，保留 100%、原生工具和 Mac 实机的真实边界。

前置临时试验仅证明加载可行：Windows Chrome 154、150% 下 611 MB 的 S09E01 缓存
约 1412 ms 可播放，按需请求约 22 MB 后完成跳转和音频解码；未授权目录、未关闭安全检查，
未调用 Provider。试验注入 API，仅是设计证据，不是正式实现通过记录。
