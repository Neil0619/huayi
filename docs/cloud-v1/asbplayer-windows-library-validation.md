## 发现及修复

旧版同轨双语要求每一个 cue 都含独立英文行和不含 Latin 的中文行，片头署名、符号、中文里的
英文名称也会使整份文件不能确认。本轮保留至少一段明确双语证据的要求，将不能确定英文的
cue 整段保留为原字幕；其时间区间优先恢复原显示，后续清楚对白自动恢复学习，偏移及重叠均
按实际时间处理。中文行中的英文名称保留，不从混排的一行里截取、猜测英文。

另修复空完整字幕快照显示空轨道选择器的问题，改为可恢复的输入检查提示；有效字幕重载后
重新进入确认流程。没有新增自动 OCR、内嵌字幕提取、媒体转码、权限、运行时依赖或 Wire 变更。

TDD 首轮 9 个新增用例中 5 个按预期失败、4 个通过；修复后整个 asbplayer 单元目录 16 文件、
125 测试通过。新增实际 Store E2E 2 项验证原字幕回退、恢复、学习收藏及空输入重载。
聚焦 lint、Store TypeScript、release 构建、diff 空白检查通过。

两个长路径 ASS 在最初自动上传时得到空文件。独立浏览器 FileReader 对照证明：普通传参路径
长度 274／312 时 File.size 为 0 且 NotFoundError，同字节短路径能读；以 Windows 扩展路径格式
传入两个原位置时能完整读取。测试脚本改用 `toNamespacedPath` 后，两份原 ASS 直接通过。
这是已确认的自动上传传参问题，未证明日常拖放有同一缺陷，不要求用户搬动整库或批量转编码。

## 剩余限制

1. 下载文件并非只看 MKV／MP4 后缀就能保证即开即用。本机抽测 DTS／AC-3 无音频解码，AAC
   可用；没有实现播放器内转码。兼容副本是已验证的输入准备方式，不是原文件已修复。
2. 图片字幕需要 OCR 并校对，压制字幕也不是可选择文本；无字幕资源需要另外提供文本。
   有内嵌 SubRip 仍需提取为外挂文本，当前扩展不自动提取。
3. 真实 YouTube 临时中文此前受翻译字幕 HTTP 429 阻塞，本轮未重复请求上游；保留未通过状态。
   离线 YouTube 回归不代替这项真实服务验证。
4. 官网测试显式拒绝本地字体权限，基础弹窗调整到常见 1000×700；默认字体请求及自动生成的
   小弹窗历史失败仍保留。其他 Store profile 官网账号业务、真实付费模型、外部词典未验收。
5. 新 shared 行为仍需 Mac 实机验收；双平台 CI 与 Windows 的通过不会替代 Mac 实机。
