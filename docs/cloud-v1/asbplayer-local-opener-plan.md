# 原 MKV 本机打开器实现与验证计划

代码已实现，完整自动门禁及正式内容脚本的 150% 真实文件学习已通过；
新界面 100%、原生文件选择／快捷方式交互与 Mac 实机验证仍待完成。
准确候选、已执行检查与边界见 [Windows 打开器回执](asbplayer-windows-opener-validation.md)。

目标：Windows 用户选择原视频后，自动准备浏览器音轨和文字字幕，再进入官网学习；
原文件只读，兼容文件缓存到本机。音频已由用户确认恢复，此次重点减少手工准备步骤。

## 已验证的接口

2026-09-24 在 Windows 150%、Chrome for Testing 154.0.8037.57、实际 Store 构建下，
本机页面取得整集 611,074,977 字节 MP4 和英文字幕，以 `File` 通过 `postMessage`
送入官网窗口，再交给官网文件输入控件。视频时长 1226.271 秒，音轨可解码，
学习桥接、合成翻译/解释、本地保存、恢复播放均通过。该次接收器为注入原型，
仅证明可行性，不代表正式内容脚本或原 MKV 自动处理验收通过。

## 实施顺序

1. TDD 验证媒体计划、文字字幕识别、只读源文件、缓存发布和失败恢复。
2. 本机 Node/FFmpeg 打开器：原生文件选择、有限相邻字幕发现、音轨转为 AAC、
   视频流复制、内嵌文字字幕提取。图像字幕明确报告不可学习，不伪造文字。
3. 仅监听 `127.0.0.1`，随机端口和会话令牌，校验 Host/Origin，浏览器不能提交任意路径；
   只服务本次选择后生成的文件，不开放通用文件服务器。
4. 官网顶层内容脚本校验一次性导入描述、准确 opener、源 origin 和 File 列表，
   将文件交给原生文件输入；不扩大扩展权限，不改变现有被动播放桥接或 Classic Host。
5. 简洁本机页面保留打开另一视频入口；字幕选择预选明确轨道，歧义保留人工确认。
6. 正式 Store 构建端到端验证、完整 Windows 门禁、双平台 CI、Git 回执。

## 验收边界

- 不修改原视频，不调用真实模型、不写外部词典、不上传媒体。
- HEVC/H.264 视频流复制；音频必要时转 AAC。其他视频编码明确提示，
  首版不承诺所有格式，不自动执行成本很高的整片视频转码。
- Mac 的纯逻辑 CI 不代表原生文件选择、启动器和实机播放通过。
- 正式导入必须用注册内容脚本验证，不能以原型注入代替。
- 稳定扩展加载路径保持现有路径；本机打开器单独安装、更新。
