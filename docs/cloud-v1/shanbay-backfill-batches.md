# 扇贝回填批次兼容约定

适用于 shared（macOS/Windows）Store 扩展及 Hosted API 的 `ShanbayBackfill` 路径。

- 新扩展向 `POST /v1/shanbay-backfill` 发送 `{ "action": "claim", "limit": 100 }`，
  每批最多领取 100 个不同目标词。`limit` 可选，须为 1–100 的整数。
- 旧客户端省略 `limit` 时，API 继续返回最多 20 个词。解析不会向旧命令补默认字段，
  旧幂等键与摘要、已领取的 20 词批次及回执继续有效。
- 本机领域核心的默认值与上限为 100。页面批次、API 回应和持久账本允许最多 100 个词。
  来源发现和迁入仍每段最多 100 项；原手动导出任务仍按原限制领取，并与回填共享目标占用。
- 每批由用户亲自点击扇贝“批量添加”。完整且明确的页面结果持久化成功后才可准备下一批；
  缺失或不明结果保留为 unknown，不自动确认或重发。

## 发布和回滚

先更新 Hosted API，再重载新扩展和刷新扇贝页面。旧 API 的 strict Schema 会拒绝 `limit`，
客户端不会以更换请求形状的方式自动重发领取。

此变化无需数据库迁移。超过 20 词的批次一旦保存，即使已经完成，旧 API 的 20 词 Schema
也无法读取该账本。回滚必须保留 100 词的读取和回执能力，可将后续新领取暂时限制为 20；
不能直接恢复旧 Schema、删除批次或改写历史成功证据。

## 验证范围

离线回归覆盖 101 词连续 100+1、旧请求 20+1、旧/新客户端幂等、100 词部分拒绝和未知结果、
旧手动导出与新回填共用 120 个目标时的互斥领取，以及超限消息/持久化拒绝。
实际扩展 bundle 的隔离浏览器验证覆盖 496 词分五批、每批独立可信点击、账本和角标归零。
部署健康与版本回读不替代真实扇贝账号或 Windows 验收。

## 未解决词批量丢弃兼容性

新命令 `{ "action": "discard-unresolved", "expectedRevision": 版本号 }` 使用现有账号鉴权、
事务、版本检查和 `Idempotency-Key`；处理所有分页的未解决词，保留待回填、成功历史及未知/在途
批次占用。变更来源以每组最多 100 条批量写入，一组失败则整次事务回滚。没有新增数据库结构。

先发布支持新 action 的 API，再交付含“全部丢弃”的扩展。旧 API 会拒绝该命令；客户端不能假报成功，
也不把它拆成多次单词丢弃绕过版本和事务约定。旧客户端单词丢弃和现有 100 词领取不受影响。
