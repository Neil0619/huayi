## 已复现并修复

1. 英文 Windows CI 的 `WScript.Shell.Save()` 无法保存中文快捷方式；本机用系统代码页外的
   桌面目录复现。改为 Unicode `IShellLinkW` / `IPersistFile`，保留新旧入口所有权核对。
2. Windows PowerShell 5.1 按本机代码页读取 UTF-8 配置，含中文和特殊字符的 Node 路径无法启动。
   真实可执行文件夹具先失败，明确 `-Encoding UTF8` 后 `.lnk` 启动成功。以上实现为 `555cfe9`。
3. 缓存清单为空、缺少视频/字幕、重复视频、类别错误或缺少处理计划时，旧代码可能返回成功。
   `9de82fa` 的六项回归先失败再修复；现在核对完整计划和实际文件，不向播放器交付不完整缓存。
4. `555cfe9` 和 `9de82fa` 的 Windows CI 已实际启动快捷方式，但测试把 PowerShell 展开的
   `runneradmin` 路径与临时目录的 `RUNNER~1` 别名判为不等。`dbaa507` 使用配置文件的
   `realpath` 比较；唯一完整参数、真实启动、迁移与无关快捷方式字节不变的断言全部保留。
5. `555cfe9` 的 Mac CI 在临时中文快捷键松开后仍暂停。真实 Chrome 可稳定复现相同症状：
   `play()` 排队的旧 `play` 事件在语见已经 `pause()` 后到达，误撤销恢复资格。
   单元和真实浏览器回归均先失败；现在只忽略自有暂停尚待派发、视频已经暂停时的旧 `play`。
   用户随后主动播放/暂停仍撤销资格，不会被错误恢复。16 项所有权单元、2 项原生媒体事件
   浏览器回归、152 项字幕和交互单元通过；Store 集成松键恢复也通过。

失败历史保留：`555cfe9` 双平台 CI 失败；`9de82fa` Windows CI 的别名比较失败。
`9de82fa` 本机完整门禁及 `9de82fa`、`dbaa507` CI 因后续真实播放修复被取消，不能记为通过。
