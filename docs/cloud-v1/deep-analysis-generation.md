# 深度分析生成边界

当前候选提示词版本为 `web-deep-analysis-v2.11-balanced`。这里描述生成与校验机制，
不表示该候选已经完成教学质量验收或发布。

## 私有输出与公开结果

模型只生成 `previewZh` 和按输入单元排列的 `result`，学习候选放在所属单元内。
API 决定原文、单元 ID、全局候选 ID 与顺序、交叉引用、模型元数据，再校验公开 v2 契约。
公开 API 和已保存的数据结构不变，无需数据库迁移。

输入不得静默截断。短语保留一个完整单元；句段最多 40 个单元，超过限制时在创建请求、
预留额度和调用模型之前拒绝。单元原文必须按顺序覆盖整个输入，仅允许单元间的空白。

教学引文和表达候选必须是所属原文单元的连续片段，不从学习者语境借用，不改变大小写、
引号、Unicode 字符或词形。新例句是独立教学内容，不受原文引用约束。

句型额外提供私有 `sourceValues`，每个声明槽位恰好对应一个原文值。API 用字面替换填回
模板并核对连续原文，不执行表达式。模板可以给没有结尾标点的标题添加一个末尾英文句号，
前提是其余字符完整匹配到原文结尾；不忽略内部标点、问号或其他字符。
`sourceValues` 不进入公开结果。公开句型的槽位数量、名称与引用约束仍然完整生效。

这一检查只能证明字面来源，不能证明槽值的句法角色、中文解释或模板的迁移质量。
把关系从句改写成独立主句的候选可能无法通过；不能通过模糊匹配或补写主语来放宽检查。

## 修复、费用与时限

当前产品配置仍为 Flash 普通模式，最多一次结构修复，两次调用共用 90 秒时限。
短语每次最多 4096 输出 token，句段每次最多 8192；研究中更高档位与更大限额不会自动进入产品。
每个实际调用分别保留可信 token 用量及费用，失败和修复同样计费。缺少可信用量时保持未知，
不能记成零。账单的峰谷时段、缓存命中和输出 token 必须分开比较。

修复接收原文和受限的原始输出，以及可公开的校验字段、阶段和 JSON 错误位置。
整个请求限制为 64 KiB；原始输出按完整 Unicode 码点截断，并计入两层 JSON 转义后的大小。
错误附近片段最多 160 个 UTF-16 单元。原始内容与片段只在修复请求中作为 JSON 引用数据，
不会写入诊断日志；推理文本不进入公开结果或日志。

修复反馈额外保留已知字段路径中有界的、从零开始的数组位置，区分不同单元和候选的同类错误。
`exact-source-fragment` 明确指出对应引文不是所属原文的连续片段。该位置只随修复请求发送；
日志仍将数组位置替换为 `*`，不含原文、模型输出、动态字段或错误消息。
反馈最多保留 16 项、每条最多 8 层；未知字段和异常位置不会产生精确定位。

## 验收要求

结构通过与教学通过分别统计，失败结果保留在总样本数中。教学审核覆盖自然译文、
事实与假设范围、语法解释、可用例句和可迁移候选；重复解释也单独记录。
调参中见过的样本只能算开发回归，最终方案须用未参与调参的新样本验证。

升级模型或启用推理必须同时记录成功率、人工质量、首个可见预览、总耗时、
首次与修复调用数、输入/缓存/输出 token，以及按同一价格时段归一后的费用。
代码测试通过不能代替真实模型路径验收，也不能代替 Hosted 与正式发布门禁。

## 有界语法提示

候选按原文中的完整单词选择两条已核对的语法提示，仅覆盖 only if 的必要条件关系和
less/fewer 的数量、宾语与修饰关系。提示是固定文本，不把用户原文或学习语境拼入系统指令，
不联网检索。表达与句型候选、公有 v2 契约和 Flash 普通模式继续保留。

提示根据 [Cambridge 的 if 用法](https://dictionary.cambridge.org/grammar/british-grammar/conditions)、
[Stanford 的必要与充分条件讨论](https://plato.stanford.edu/entries/necessary-sufficient/)、
[Cambridge 的 less/fewer 用法](https://dictionary.cambridge.org/grammar/british-grammar/fewer-or-less)、
[宾语说明](https://dictionary.cambridge.org/grammar/british-grammar/direct-objects)
和 [被动句说明](https://dictionary.cambridge.org/grammar/british-grammar/passive-forms)编写。
条件提示保留自然语言的语境限制，不把全部 if 用法机械转成形式逻辑。
数量提示区分语义上的受事与句法上的宾语，保留被动句主语这一反例。

这不是完整语法知识库。早期精简研究格式与产品格式不同，不能借用其成功率。
2026-09-08 已使用保留表达与句型的实际产品适配器验证，另行记录结构可用与人工质量。
语法标签也可能误判；通用提示要求核对实际词形、语序及限定词，不以术语堆砌代替解释。
形容词补语与被动形式的依据见上述被动句说明及
[Cambridge 的形容词宾语补语说明](https://www.cambridge.org/elt/blog/2021/10/26/paint-the-town-red-adjectives-as-object-complements/)。

## 实用质量与局部恢复

当前候选优先可理解的译文、少量有迁移价值的重点和较低等待成本，不要求每句话填满结构、
语法、表达与提醒。只请求 1–2 个主要教学点、少量生成例句，并使用紧凑 JSON。
缺少次要知识点、术语可换一种说法、例句数量不同，不单独作为整份分析失败的依据。
否定、人物、事实范围和关键含义仍需人工核对；结构测试不证明语义总是正确。

服务器先用既有严格解析器检查。对于已经具有完整原文对应关系和译文的结果，可以丢弃
可选教学/建议数组中格式无效、引文不连续或句型不能重建原文的单个项目。
不重写模型的引文、槽值或解释，不用猜测补全结果；数组原有数量上限、未知外层字段、
必填内容、单元数量及最终公有契约校验保持不变。其他项目与原文解读保留，编号和引用
仍由服务器重新生成。日志只记录固定类型和数量，不记录原文或解释。

JSON 语法损坏、缺少译文或单元、整体结构错误仍最多修复一次，两次共用原有 90 秒期限。
可局部恢复时不再为整份答案额外调用模型；没有改用更贵的模型。已有使用量与失败计费
路径继续覆盖所有真正发出的调用。输出 token 上限是安全边界，不代表要求模型写满。

没有学习建议时 Web 保留解读，并明确提供重新分析或标记无需学习的路径。
任务超时或服务异常会保留原文；终态失败/取消清除尚未验证的预览，重新分析失败时标明
下方是上一次完成的结果。连接结果不确定时先核对原任务，不能自动重复提交付费分析。

2026-09-08 的冻结评估将“实用、较快、少 token、有恢复路径”作为取舍依据，采用
good / usable / weak / failed 分档；允许记录非关键不足。已知案例的重放只验证项目恢复机制，
另用未发送的新材料检查输出稳定性。必须分别报告结构可用率、人工实用性、调用/修复数、
首个预览/总耗时和 token，不将少量样本或删去无效建议后的成功说成模型无错误。
