# Windows 指定媒体无声与内嵌字幕复验

2026-09-24，用户在日常 Chrome 报告单个 MKV 有画面、无声，并询问内嵌字幕为何没有加载。
用户已确认只导入视频。本回执追加验证盘点编号 `media-470`，与[首轮影视库扩测](asbplayer-windows-library-validation.md)
中的 9 个原文件分别计数；原媒体、字幕正文、文件名和路径不提交到 Git。

## 原文件复现

ffprobe 重新读取原文件：HEVC Main 10、1920×1080，英文 AC-3 5.1 音轨，一条英文 SubRip
内嵌字幕，时长 1226.272 秒，大小 620,098,745 字节。用户关于存在内嵌字幕的判断正确。

将原 MKV 单独导入实际官网：画面播放通过，帧数从 4 增到 83；音频解码字节 0、捕获音轨 0、
video.textTracks 为 0，语见状态为 `waiting-full-snapshot`，没有可用文本学习输入。
Provider 请求为 0，结果为 partial、退出 2。不是将静音或加载超时当作正常播放通过。

这一对照说明当前浏览器播放链路没有解码该 AC-3 音频，也没有把 MKV 中的英文 SRT 提供给
语见学习层。当前产品不自动提取内嵌字幕；导入视频不会自动取得同目录外挂 ASS。
截图中的等待提示发生在收到完整字幕和偏移之前，并不能仅靠截图判定是哪一种输入问题。

## 已准备的完整兼容输入

在用户影视目录下新建独立、短路径的兼容副本目录，原文件未覆盖：

- 整集 MP4：`-c:v copy -tag:v hvc1` 保留视频编码，首条音轨转 AAC、双声道、192 kbps，
  `+faststart`；不携带内嵌字幕。没有 `-t` 截断，容器时长仍为 1226.272 秒、611,074,977 字节。
  音频是有损转换并由 5.1 下混到双声道，不称为无损音轨。
- 从原 MKV 的英文 SubRip 流直接复制提取 SRT，25,631 字节、342 个字幕段。
- 找到同集已有中英双语 ASS，按原字节复制到同一短目录，152,656 字节；没有拆轨或改编码。

处理前后原视频 SHA-256、大小与修改时间均一致；ASS 副本与来源字节一致。实际媒体及包含本机
路径的临时工具／回执只保留在本机，不进入仓库。没有扩展权限、生产依赖或解码架构变更。

AAC 解码器为 `FFmpegAudioDecoder`。浏览器媒体时长为 1226.271 秒，与容器元数据的毫秒差异如实保留。
这是完整文件加三个位置抽查；没有主观听完整集、校对全片字幕同步或验证所有声道。

使用时把兼容 MP4 与同集双语 ASS 一起导入 asbplayer，英语和中文选择同一轨后确认。
仅需英文时，改为导入 MP4 与提取的英文 SRT，中文选择“无中文轨道”。不要同时加载两份包含
重复英文的字幕，除非用户明确要使用多轨。原 MKV 本身的浏览器限制没有因此消失。
