# 语见自动错误采集与管理页

状态：已接入本地代码；尚未提交、部署、执行远端迁移或启用线上采集。验收结果以本次任务最终回执为准。

用户决策：实现自动采集和管理后台报错日志页面。**不实现自动代码修复**；后续业务问题只能在用户明确要求时修改。

## 当前实现

- API 为每个 HTTP 请求生成关联编号，并通过 `X-Request-Id` 返回。异步上下文将账号、请求、任务、生成编号关联起来。
- 模型供应商非 200 响应保留状态码；网络、流协议、输出校验和任务终态分别记录固定阶段。输出校验只保留白名单字段路径和规则。
- 流式生产者结束后等待日志落库，避免 HTTP 200 响应头已经返回但后续模型失败未被记录。
- 既有学习任务 worker 每次运行时清理过期日志并补采失败/未知任务；该操作只读取任务状态，不重试业务或调用模型。
- Store 插件的当前查询引擎覆盖 BYOK 和平台路径。在独立诊断同意开启且已连接账号时自动上报，不要求用户逐次反馈。
- `/admin/error-logs` 展示来源、错误/警告、时间、错误码、阶段、HTTP 状态、版本、耗时和关联编号。可按时间、来源、级别、编号筛选，分页查阅与手动/30 秒自动刷新。
- 统计包括事件数量、错误事件、影响用户、关联请求/任务、高频问题。一次请求可有多条阶段事件；这些数量不是全站失败率。

## 分级和隐私

此模块只采集诊断事件，分为 `warn` 和 `error`，不采集常规成功请求和正文。模型输出校验失败等可恢复诊断记警告，最终任务失败记错误；用户取消不计入任务错误。
不会序列化 Error 对象、异常消息/堆栈、请求体、原文、回答、URL、标题、Cookie、Authorization 或密钥。
字段、错误码、阶段、供应商、版本格式、关联 UUID 与校验规则均通过严格共享契约验证。客户端不能自选账号或冒充 API 来源。

## 可靠性与边界

- 插件 outbox 上限 100 条、256 KiB，24 小时过期；每批最多 20 条，以事件 UUID 去重。
- 每条日志绑定发生时的同意版本和会话摘要。会话摘要不上传，不保存会话 token；换号或关闭诊断时旧记录不会上传到新账号。
- 断网及服务端暂态错误按 1 分钟至 1 小时退避。上报单次超时 10 秒；401/403/426 停止旧队列重试。
- 服务端按认证账号限流，上传体最多 32 KiB。诊断故障不改变模型校验、账单或业务返回；数据库不可用时写入已有平台日志，仅包含同样的安全元数据。
- 错误详情查询窗口最多 30 天。每次入库及既有 worker 运行清理最多 1000 条过期记录；停用 worker 且没有写入时物理清理会延后，查询仍不返回超期记录。
- 管理日志 GET 要求 active/full Web 会话和显式 Operator 角色，不要求近期重新认证；表启用 RLS，公开角色和普通业务角色无读写权限。
- 账号删除通过外键级联清除关联诊断。
- 未授权、未配对、旧版插件、Classic 0.13/Native Host 不在当前后台采集覆盖内。Web 已到达 API 的请求由服务端采集；浏览器自身崩溃和完全未到达 API 的网络故障不在当前 Web 采集范围内。
- 当前仅有错误事件统计，没有成功请求分母、全站错误率、外部消息告警或自动修复。

## 发布顺序

本次不部署。后续明确要求发布时，应先应用 `0027-error-diagnostics.sql`（Supabase 镜像 `20260907020000_error_diagnostics.sql`），再更新 API、Web 和 Store 插件。

更新后的插件在常用设置中展示诊断用途、接收方和保留时间；既有用户不自动转为同意。后台入口位于运营控制台“报错日志”。
