# Windows 原视频打开器

影响 `shared + Windows`。此打开器是本机开发工具，不是商店扩展的后台进程，
不修改 Classic Native Host。扩展加载路径与 ID 保持不变。

## 使用

1. 启动本机打开器，在 Chrome 中点击「选择原视频」，选择 MKV 或 MP4。
2. 首次会在本机准备兼容音轨与内嵌文字字幕；原视频只读，视频画面不重新编码。
   同一文件再次打开时复用完整缓存；源文件变化后重新准备。
3. 优先勾选唯一的相邻中英双语字幕，否则优先内嵌英文文字字幕。可修改勾选，
   或通过「添加文字字幕」选择其他 SRT/ASS/VTT；最多同时导入三份文字字幕。
4. 已处理的视频可点击「打开缓存视频」，选择「缓存视频」中的对应 `.浏览器.mp4`。
   打开器校验缓存记录并自动匹配字幕，无需原片存在，不再转音轨。再次选择原片也优先复用有效缓存，
   显示「已找到缓存，直接使用」；缺少或已修改的缓存不会被当作有效结果。
5. 直接点击「开始学习」，无需复制路径或再选择/授权缓存目录。视频通过本机 Range 流按需读取，
   字幕单独读取；不会先把整部视频下载成 Blob。Chrome 首次可能要求允许官网访问本机服务，
   需要按浏览器提示允许；拒绝时播放器显示「重试本机播放」。这项网站权限与目录授权不同，
   不能关闭浏览器安全检查来替代。完整内容明确时，学习层预选中英文轨道，点击确认即可。
6. 换片时点击播放器页「打开另一个视频」，直接弹出原生选片窗口；准备好后到打开器点击「开始学习」。
   按钮通过限定来源、窗口和当前导入 nonce 的请求触发选片，不依赖 Chrome 是否响应窗口置前。
   忙碌、打开器已关闭或没有响应时会显示提示，不静默失败。
   新文件交接成功后，打开器会通过受限消息结束上一轮由它创建的播放器，避免同时播放；
   已跳转到其他网站的页面不接收这条消息。播放器内全屏时先退出全屏。
   完成后点击打开器的「退出打开器」。

仅打开原 MKV 到官网本身，仍可能没有声音或字幕；自动准备发生在这个本机打开器中。
无内嵌文字字幕、只有 PGS/VobSub 等图像字幕时会提示，需要另外提供文字字幕。
首版支持 H.264/HEVC 视频；Chrome/硬件仍须支持对应视频解码。
优先使用标记为英文的音轨，否则第一条音轨；当前不提供多音轨切换。
不会自动 OCR、翻译整片或转码整个视频画面。

## 批量预处理

点击「批量预处理视频」，在 Windows 文件窗口按 Ctrl / Shift 多选视频（最多 500 个）。
打开器逐个准备音轨和文字字幕，不打开播放器。
每项显示片名、进度、成功或失败，以及成功后的缓存目录。一项失败会继续后面的文件。
缓存仍在每个原视频旁的「缓存视频」中，命名和单片流程一致；有效缓存不会重复转换。

「停止剩余任务」会完成当前文件，再跳过后面的项目，保留已完成缓存。处理期间不能另开
准备任务或退出打开器，避免同一缓存的并行写入。关闭网页不会停止本机进程中的队列；
再次双击桌面入口可查看结果。退出本机进程会丢失队列列表，但已完成缓存长期保留。

批量结束后点击某项的「选用此视频」，或以后通过「选择原视频」重新选择原文件，都会
验证并复用缓存，直接点击「开始学习」；也可通过「打开缓存视频」选择已生成的文件。没有文字字幕时仍需另选字幕，批量处理
不会增加 OCR 或视频编码支持范围。未处理和失败的文件可以重新多选，成功项自动复用。

更新后请先退出旧打开器，再从桌面入口启动，并在 Chrome 扩展页重新加载同一固定路径的
语见扩展，然后重新打开播放器。正在运行的旧网页不会自动换成新版代码。

## 本机配置与启动

需要 Node.js 26、FFmpeg、ffprobe 和加载了语见的 Chrome。配置 JSON 仅存于本机，示例：

```json
{
  "node": "C:\\Tools\\node\\node.exe",
  "ffmpeg": "C:\\Tools\\ffmpeg\\bin\\ffmpeg.exe",
  "ffprobe": "C:\\Tools\\ffmpeg\\bin\\ffprobe.exe",
  "chrome": "C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe"
}
```

```powershell
node scripts/asbplayer-open.mjs 'C:\Users\your-name\AppData\Local\SeenSaid\opener.json'

# 安装/更新固定目录和桌面快捷方式，保留已有配置：
node scripts/install-asbplayer-opener.mjs 'C:\Users\your-name\AppData\Local\SeenSaid\opener.json'
```

新缓存固定放在原视频旁的 `缓存视频` 文件夹，保留片名和集数，例如：

```text
剧集目录/
  Show.S09E01.mkv
  缓存视频/
    Show.S09E01.浏览器.mp4
    Show.S09E01.英语.轨道2.srt
    缓存记录/    （小型校验记录，不是另一份视频）
```

不同来源的同名文件、用户已有文件或损坏缓存不会被覆盖；新结果以 `(2)` 等编号区分。
极长名称保留首尾，限制单个文件名长度。相邻字幕搜索排除生成的缓存目录，避免重复导入同一轨道。
原目录必须允许创建缓存；只读或空间不足时明确失败，不静默改存到项目目录。

已有配置中的 `cacheRoot` 仅作为旧缓存迁移来源；没有该字段时尝试旧的
`%LOCALAPPDATA%\SeenSaid\media-cache`。完整旧缓存复制到新位置时不重新转码，旧文件保留。
迁移期间两处各占一份空间；确认新缓存可用并关闭相关播放器后，可自行删除不再需要的旧缓存。
后续学习只复用新位置，浏览器按需读取，不再额外保存整部视频。旧版已保存的目录句柄不再使用。
首次准备仍需要一份接近原视频大小的兼容文件；关闭打开器和播放器后可删除不需要的缓存，原视频不受影响。
失败的临时目录清理后可重试。
复用前验证完整处理计划、唯一视频、全部预期字幕、文件类别、大小与实际文件；
空清单、缺失字幕或缺少处理计划不能成为“已准备好”的缓存。

安装器使用固定目录 `%USERPROFILE%\SeenSaid\asbplayer-opener` 和桌面「语见本机视频」快捷方式，
隐藏启动终端；PowerShell 执行策略仅为该启动进程设置，不更改系统策略。更新时仅更新打开器脚本，
保留本机配置、依赖和缓存。`browser-origin.json` 保存在安装目录中，包含本机端口身份和私密密钥，
不得提交或分享。重复启动复用当前打开器；退出再启动保持浏览器 origin，实际会话令牌会轮换。
不要在主仓库旧提交上重建已加载扩展；开发工作树通过验证后再同步产物。

该目录位于 AppData 之外，避免从 MSIX 打包的开发应用安装时发生文件虚拟化：开发进程能读到的
AppData 文件，可能实际位于该应用的私有 LocalCache，资源管理器双击时却提示脚本不存在。
首次迁移优先采用旧 `%LOCALAPPDATA%\SeenSaid\asbplayer-opener\config.json`，新目录已有配置时
优先保留新配置；旧配置与媒体缓存不删除。桌面入口仅允许更新准确匹配的本工具新旧快捷方式，
其他目标或参数的同名入口不会被覆盖。不要把快捷方式指向某个开发应用的私有包目录。

验证必须从资源管理器或桌面实际打开快捷方式，确认 Chrome 页面和选片窗口；仅从开发终端运行
脚本不能证明桌面入口可用。详细根因和实机证据见 [Windows 桌面启动修复回执](asbplayer-windows-launcher-validation.md)。

文件选择使用临时的置顶窗口作为对话框所有者，避免隐藏终端启动的选择窗口被 Chrome 遮住。
选择或取消后同时释放对话框与临时窗口，不留下常驻置顶窗口。若仍未出现选择窗口，或启动终端
闪过红字，应分别记录发生在双击快捷方式还是点击「选择原视频」之后，不能视为同一故障。

## 数据与验证边界

- Node 仅监听 `127.0.0.1`。首次选择空闲端口后保存本机身份，之后保持该端口。
  重复启动通过随机挑战的 HMAC 证明确认已有进程，不向未经验证的占用进程发送会话令牌。
  会话令牌通过 URL fragment 一次交给本机页面，
  随后从地址栏移除；请求使用 Authorization，校验准确 Host 和 Origin。
- 网页不能提交任意本机路径，只能触发原生文件选择；相邻字幕搜索只在视频所在目录和下一层，
  限制遍历量。字幕下载只接受本次选定文件的随机 ID；旧的视频下载入口仍返回 410。
- 对已选缓存签发 256 位随机只读 `/stream/<64hex>` 能力地址，仅接受 GET/HEAD 与单个字节范围。
  准确 Host 必须匹配；携带 Origin 时只能是本机页面或官网。无 Origin 的媒体请求也必须持有能力。
  每次读取校验真实路径、文件身份、大小和修改时间；不接受查询参数、任意路径或外部主机。
  最多保留四个播放能力，之后淘汰旧项；最多 16 个活动响应，退出进程立即全部失效。
  地址是私密访问能力，不得写入日志或分享；官网已获准访问选中的视频，不能将它视为对官网保密。
- 官网通过准确 opener、origin、单次 nonce 接收视频描述和选中字幕。MAIN world 为这个导入的
  单个占位 File 临时映射 `URL.createObjectURL`，返回本机流地址；消费后、10 秒超时或离页恢复，
  其他 File/Blob 保持原生行为。上游文件输入并非正式公共协议，更新后必须回归真实官网。
- 播放路由只允许原有官网 blob 或准确的 `http://127.0.0.1:<非特权端口>/stream/<64hex>`。
  内容脚本与后台共用流地址校验。视频采用匿名 CORS，保留声音捕获和画面读取能力；
  拒绝本机访问时显示重试提示，不能以普通播放成功代替学习和捕获通过。
- 媒体、能力地址及本机路径不进入语见业务消息、Provider 请求或 Git。用户划词后仍按既有
  同意和 Provider 设置工作；本机流不意味着上传媒体，但官网脚本处于被授权的媒体信任边界。
- 不增加扩展 Manifest 权限，不依赖 Native Messaging，不修改账号、外部词典或系统文件关联。
  Chrome 的网站本机访问权限由用户正常授予，不绕过浏览器安全机制。
- FFmpeg 用于本机解码/封装，采用外部本机可执行文件，不加入扩展依赖。
  对比纯浏览器 WASM，此方式避免整集转码的浏览器资源限制；不引入远程执行服务。
  媒体解析器仍需保持更新；本仓库不重新分发 FFmpeg 二进制。

测试分开记录：核心单元测试、正式扩展离线文件交接、官网完整学习流程、原生文件选择和快捷方式。
自动注入一个已知选择结果只能证明媒体处理与浏览器链路，不能证明原生文件选择窗口可用。
macOS 原生打开器尚未实现；共享内容脚本须通过双平台 CI，不能把 Windows 实机结果当作 Mac 通过。
