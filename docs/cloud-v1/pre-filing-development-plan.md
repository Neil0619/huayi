## P1：小程序关键流程

1. 补齐登录页面级回归：微信登录、独立开通、选择关联、绑定待确认/过期/失败和重新选择入口。保持首次关联可选，不引入账号记录合并。
2. 核对列表切换时的真实呈现：收集箱、学习库和历史在加载、失败、筛选、翻页和重新进入页面时，内容与当前查询一致。
3. 核对账号状态变化时的旧数据清理，避免退出/换号后继续呈现之前账号的资源。以实际失败测试确认根因，再做限定修复。
4. 保持前一轮草稿、幂等请求和后台任务恢复回归。每个行为改动先观察红灯，再验证修复后的实际 Hook 或页面。

验收：小程序全套本地测试、源码 lint/格式、类型检查、实际 weapp 构建。React/Taro 组件适配测试证明页面逻辑，不替代原生组件、键盘或真机交互。

## P2：当前 API 与数据链路

1. 复用现有 PGlite 和 Hono 测试端口，把与微信账号、绑定、数据权利和生词归档有关的组合流程放到当前完整迁移链上验证。
2. 重点验证独立微信账号、关联原网页账号、跨账号读取/写入被拒绝、会话撤销，以及实际数据操作和最终数据库结果的一致性。
3. 保留专门的迁移镜像一致性与权限测试。只有组合测试证明需要时才调整实现，不为了测试便利加入生产鉴权绕过。
4. 网络供应方使用既有可注入测试端口；测试不访问微信、邮件、存储供应方或模型服务，不消费账号额度。

验收：组合测试及受影响现有测试通过；数据库在测试自身作用域创建/销毁，不停止、重置或迁移任何已有验收数据库。PGlite 结果不冒充云端 PostgreSQL、真实调度并发或线上迁移验收。

## P3：轻量官网

首版复用 `apps/web` 和现有品牌、四套外观主题，采用公开首页与使用帮助。官网定位为个人及朋友了解语见、理解学习方法和找到入口的地方。

- **公开首页 `/`**：标准品牌与 slogan、产品介绍、收集→理解→练习的完整流程、插件/网页/小程序分工。
- **交互示例**：用内置英文示例切换阅读、理解和造句展示，明确为示例；不调用模型，不收集访客输入。
- **使用帮助 `/guide`**：首次使用步骤、微信独立开通与可选关联说明、三端适用场景、草稿和数据控制的简明说明。
- **入口状态**：网页使用现有登录/工作台路径；尚未开放的小程序或插件安装入口显示准备状态和可用帮助，不显示虚构二维码、商店链接或安装包。
- **隐私和联系**：链接已有公开 `/privacy`，复用已确认维护者联系方式；不新增数据采集表单或跟踪脚本。

实现条件：公开页面在 API 配置缺失时仍能加载，不创建身份或业务 API 请求；保持现有 `/login`、`/join`、恢复、配对和工作台路由的行为。新增页面使用局部 CSS 与既有语义 token，不更改全站主题定义。

视觉与交互验收：320/390/768/1440px、四套主题、横屏、200% 文本缩放、减少动态效果偏好；检查横向溢出、焦点可见、导航、示例切换、帮助和隐私入口。截图必须来自实际构建产物。

## P4：统一验证与交付

新增 `node scripts/verify-pre-filing.mjs`，统一顺序执行本计划的本地检查，保留结构化回执。命令必须失败即停，并说明失败步骤；不在验证过程中部署、运行迁移到已有数据库、启动真实模型或自动修复源码。

检查范围：

1. 小程序全部测试，API 组合与相关回归，官网/公开路由/现有绑定页面测试。
2. 受影响文件或包的格式、lint 和类型检查；共享依赖先构建，再构建 Web 与 weapp。
3. 使用隔离的本地浏览器测试配置验证真实 Web 构建；只提供本地静态资源和明确的测试响应，阻止第三方网络。
4. 检查小程序包没有测试支持模块，官网没有外部字体/跟踪资源；保留检查范围、时间、文件摘要和产物路径。
5. 更新本文件状态与 `apps/miniprogram/README.md`，记录实际命令、数量、截图、已知问题及下一步。
