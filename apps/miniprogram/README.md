# 语见 · Seen & Said 微信小程序

首版为原生微信页面：今日练习、收集箱、学习库、我的；其余页面承载登录、收集、分析、学习项目、练习与历史。小程序使用 React 18.3.1，Taro 包统一固定 4.2.1，网页仍使用 React 19。契约从 `@huayi/cloud-contracts` 公开入口复用。

## 本地构建

在仓库根目录执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter @huayi/learning-domain --filter @huayi/cloud-contracts build
pnpm --filter @huayi/miniprogram typecheck
pnpm --filter @huayi/miniprogram test
pnpm --filter @huayi/miniprogram build
```

产物为 `apps/miniprogram/dist`，可以作为微信开发者工具项目导入。没有配置时使用游客 AppID，API 地址为空，网络操作显示配置提示；离线编译不代表已经连接验收环境。客户端没有内置账号、密钥或测试绕过。

真实联调时，设置以下两个非秘密构建变量后重新构建：

```sh
export HUAYI_MINIPROGRAM_APP_ID=wx替换为自己的AppID
export HUAYI_MINIPROGRAM_API_ORIGIN=https://替换为已备案的接入域名
pnpm --filter @huayi/miniprogram build
```

AppID 必须是 `wx` 加 16 位十六进制字符，地址必须是 HTTPS origin，不带路径、端口、结尾斜线。构建脚本写入产物中的 `project.config.json`，不修改源码模板。调试增量构建可运行 `pnpm --filter @huayi/miniprogram dev`；它会重新复制游客配置，因此真机联调、预览和上传前使用完整 `build`。

## ICP 备案审核期间

本轮工作与验收范围见 [备案前开发计划](../../docs/cloud-v1/pre-filing-development-plan.md)。在仓库根目录运行统一检查：

```sh
node scripts/verify-pre-filing.mjs --list
node scripts/verify-pre-filing.mjs
```

检查失败即停，回执与截图写入被忽略的 `artifacts/pre-filing-validation/<时间>/`。命令固定使用游客 AppID 和空小程序 API 地址，网页构建使用仅供隔离测试的 `https://api.huayi.invalid`；产物用于本地验收，真实联调前按下文重新构建。不会重置已有数据库或启动真实微信、模型、邮件服务。API 组合回归的数据库由测试单独创建、销毁。

域名暂停解析不影响本地构建和离线测试。审核期间可以使用真实 AppID 构建，但将 `HUAYI_MINIPROGRAM_API_ORIGIN` 留空；产物可导入微信开发者工具检查编译。登录会先检查配置，缺失时显示提示，不调用隐私授权、微信登录或业务 API；已记住登录状态的自动续期也先检查配置。它不是已接入服务的体验版，也不能验证完整页面交互。

- 先完成客户端、API 契约、账号隔离、草稿和任务恢复的离线测试，使用本地测试数据库检查迁移。
- 页面与交互验证需要本地测试数据及测试服务，不能用离线单元测试结果代替微信开发者工具或真机结果。
- 整理 DNS 恢复记录、部署配置、数据库备份和迁移顺序；等待审核通过再恢复对外访问和配置真实联调域名。
- 审核期间的开发不要求提前选择 COS、CDN 或云函数转发；最终入口由备案接入要求和实际网络验证决定。

## API 与迁移

1. API 先应用 `0029-wechat-miniprogram.sql`、`0030-word-archive.sql`（对应 Supabase 镜像迁移），再发布本次 API 和 Web。应用迁移前按现有流程备份、验证候选和目标身份。不要直接重新运行基线迁移。
2. 仅在验收 API 的服务端秘密配置中设置 `HUAYI_WECHAT_APP_ID`、`HUAYI_WECHAT_APP_SECRET`。两者必须成对出现，缺省时微信登录入口关闭。**AppSecret 不属于客户端构建变量，也不能进入仓库或小程序包。**
3. 继续使用当前数据库、默认额度、模型费用控制和持久任务 worker。学习任务与数据导出的已有 worker 调度必须可用，创建导出任务本身不会完成文件生成。此次代码没有安装 Cron、修改线上配置、执行迁移或调用真实模型。
4. 确定并验证小程序 HTTPS API 入口。可以先验证现有验收 API 域名是否满足微信合法域名配置和真机访问要求；如采用转发入口，将上游固定到 `https://api.acceptance.seen-said.cn`。备选反向代理模板位于 `deploy/nginx.conf.example`，使用前替换并检查所有占位符、证书和 DNS 配置。ICP备案资源的选择本身不要求业务请求必须经过云函数。
5. 微信后台的 request、downloadFile 合法域名均配置为最终验证的 API 入口。网页的一次性绑定确认继续走网页原来的 API 和 Cookie/CSRF 链路。

新账号的邮箱为空；Web 密码/Google 登录方式枚举保持原样，微信身份独立存储。管理列表已支持无邮箱账号。`AppID + OpenID` 的加盐摘要映射内部用户 ID；数据库仅保留会话、绑定码与凭证摘要，不保存微信 session_key。

## 开通与关联

- 微信登录后，未开通用户明确选择“直接开始使用”或“关联已有账号”。直接开通不需要邮箱、手机号或邀请。
- 选择关联时，在网页“账号与额度”中输入小程序展示的十位绑定码，完成密码或 Google 近期验证，勾选共用数据确认，再回小程序完成开通。
- 绑定码与发起微信身份的临时 ticket 成对，10 分钟过期。绑定码不能用作登录凭证，也不能借用插件配对码。已独立开通的微信身份不能用本流程合并旧记录。
- 关联页可以返回选择开通方式；绑定码过期或登录中断时可以重新微信登录，获取新码后清除旧的状态提示。
- 绑定成功后使用原 `userId`，不复制学习库、练习排期或额度。已归档内容合并候选时仍保留其原来的排期和归档状态。

## 恢复、输入与权限

- 会话只存在内存中，最长 24 小时。设备仅保存“是否曾登录”的布尔偏好；重启使用 `wx.login` 重新换取。请求过期时只重新认证并重试一次，沿用相同请求与幂等键。
- 原文、练习草稿和待确认请求按用户 ID 隔离存储。保存收集不调用模型；分析与反馈只由用户操作触发。收集原文和练习答案超过输入限制时仍完整保存在本机，并提示缩短后再提交；超长练习草稿不会同步到服务端或随暂停等操作提交。
- 分块事件使用平台无关 UTF-8/SSE 解析；不支持或失败后使用已有 JSON 游标接口。后台或页面隐藏只终止订阅，恢复同一任务；只有点击“停止任务”才取消服务端任务。
- 提交后保留答案，直到服务端的新练习记录明确包含该答案；重启恢复和晚到响应只清理已确认的旧提交，保留后来改写的草稿。晚到响应不能覆盖较新的自评或控制状态。断线时保留幂等键，收到确认后才允许新操作使用新键。
- 收集保存期间继续编辑时，旧请求完成只清理与其保存内容一致的草稿；新原文、类型、标题或上下文仍保留在本机，返回收集页后可以继续编辑。
- 表达、句型与生词均可归档/恢复。生词 V2 列表按归档状态筛选，V1 网页/插件响应形状不变，仍可查看全部生词；词表导出包括已归档生词。全部数据导出保留归档时间。
- 小程序可查看词书任务，不能创建或控制桌面桥接任务、领取插件租约、访问即时查询或取得管理员权限。网页账户安全操作仍需 Web 会话及 CSRF。
- 导出下载要求近期微信验证，文件从同一 API 域名流式提供；客户端不接触存储签名 URL。临时文件在保存/分享窗口关闭后删除。
- 注销要求近期微信验证和两次确认；关联账号会删除两端共用数据。删除任务先冻结实际身份类型，纯微信账号不会调用 Supabase Auth 删除；既有 Web 账号仍按原流程清理。

## 验收与交付边界

本轮新增查询与账号切换回归：切换学习库类型时立即隐藏旧列表和旧游标，忽略迟到和隐藏期间的响应，历史列表加载失败时仍可返回第一页。退出或换号后，分析、练习与编辑页清除或隐藏原账号镜像；同账号重新认证可以恢复本机练习草稿。编辑旧项目尚未加载完成时不能误走新增保存。真实请求包装器覆盖一次 401 续期、请求体/幂等键保留和账号 epoch 变化。

本地自动检查覆盖身份交换、独立开通、一次性关联、过期与重复绑定、会话隔离、数据导出/注销、共享迁移、草稿/幂等键、UTF-8 分块与游标恢复。草稿回归还通过 React Hook 和页面测试覆盖练习重启、保存中继续编辑、迟到响应和超长答案；测试使用本地假 API 与组件适配，不能替代微信原生粘贴、键盘和真机验收。构建输出模块清单在被忽略的 `artifacts/miniprogram/bundle-report.json`，用于检查 React 版本、包体积和依赖是否进入微信产物。

Taro 4.2.1 的部分第三方类型声明不兼容严格检查，因此仅本应用对外部声明使用 `skipLibCheck`；应用源码仍启用仓库的严格类型选项。Webpack 进度条存在新版兼容问题，构建仅移除该进度条插件，编译错误与诊断仍保留。

依赖审计并非零告警：首次 `pnpm audit --prod` 报告 17 项（1 严重、5 高、11 中），位于 Taro 引入的 H5/构建依赖，包括 swiper、webpack-dev-server、esbuild、PostCSS、nanoid、brace-expansion、qs、uuid。实际微信模块清单中不包含这些告警依赖；小程序只构建 weapp，不开启 H5 开发服务器。不要据此将 H5 发布或开发服务器暴露到网络；启用这些功能前必须升级相关依赖并重新评估。此次没有为消除审计数字而跨主版本替换 Taro 的内部依赖。
